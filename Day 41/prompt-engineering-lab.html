Stage 01 · Foundational

Foundations & Zero-Shot Prompting

Every technique you'll learn later is just an addition on top of this stage. Get the anatomy right first, and everything else is a variation on a theme.

The Anatomy of a Prompt

A prompt is not just "what you type" — it's a small, structured brief. Most effective prompts contain some combination of five parts: a persona/role, the task or instruction, supporting context, the actual input data, and the desired output format. Leaving any of these implicit forces the model to guess.

Zero-Shot Prompting

Zero-shot prompting means asking the model to complete a task with no worked examples — you rely entirely on its pretrained knowledge plus the clarity of your instruction. It's the default mode for most everyday requests, and it works well precisely when the anatomy above is filled in.

Analogy

Zero-shot prompting is like walking up to a chef and saying "surprise me" versus saying "a light seafood dish, no dairy, ready in 20 minutes." Both are zero-shot — no example dish was shown — but only one gives the chef enough to work with.

Role Prompting

Assigning a persona ("You are a senior data analyst…") is a lightweight way to prime tone, vocabulary and depth without writing a longer instruction. It doesn't grant new abilities, but it narrows the space of plausible responses.

Comparing Vague vs. Engineered Prompts

Vague PromptEngineered Zero-Shot Prompt
"Write about our new app.""You are a product marketing writer. In 3 short paragraphs, introduce our new budgeting app to first-time users. Emphasize ease of use. Avoid jargon."
"Fix this code.""You are a senior Python reviewer. Find and fix any bugs in the function below. Return only the corrected code in a code block, followed by a one-line explanation of each fix."
"Is this email good?""Review the email below for tone and clarity, assuming the recipient is a busy executive. List up to 3 specific improvements as bullet points."
Practical Exercise — Spot the Better Zero-Shot Prompt

Task: get consistent, well-formatted release notes from a raw changelog. Which prompt is best engineered?

Common Misconceptions

✕
"More words always make a better prompt."

Length without structure just adds noise. A short, well-anatomized prompt outperforms a long, unstructured one.

✕
"The model will always infer what I meant."

It infers the most statistically likely interpretation — which often isn't your intended one. State it.

✕
"Being polite or rude changes the model's ability."

Politeness doesn't unlock capability; specificity does. Courtesy is optional, clarity is not.

Key Takeaways

  • A prompt is a brief: persona, task, context, input, and output format.
  • Zero-shot relies on clarity alone — no examples are given.
  • Role prompting narrows tone and scope, it doesn't add new knowledge.
Stage 02 · Building

Few-Shot Prompting & Output Structuring

Zero-shot tells the model what to do. Few-shot shows it — and showing is often far more reliable for matching a precise format or style.

What Few-Shot Prompting Is

Few-shot prompting means including one or more worked examples ("shots") in the prompt before the real input. The model completes the pattern it sees, a capability often called in-context learning — it isn't retraining, it's pattern-matching within the conversation.

Analogy

Few-shot prompting is like onboarding a new hire by walking through two solved tickets before handing them a similar one — versus just saying "handle tickets like these" with no examples at all.

Controlling Output Format

Delimiters (###, triple backticks, XML-style tags) and explicit schemas ("return JSON with keys: title, summary, tags") remove ambiguity about where input ends and output begins, and how the response should be shaped for downstream parsing.

Without Delimiters

Summarize this: Q3 revenue grew 12%, driven by...

With Delimiters & Schema

Summarize the text between <doc></doc> tags. Return JSON: {"summary": string, "keyMetric": string}.

Zero-Shot vs. One-Shot vs. Few-Shot

ApproachBest ForTrade-off
Zero-shotSimple, well-known tasksLowest token cost, least format control
One-shotEstablishing a single format quicklyRisk of over-fitting to that one example's quirks
Few-shot (3–5)Precise style/format matching, edge casesHigher token cost; example order/bias matters
Practical Exercise — Well-Formed Few-Shot Block

Which set of examples is best formatted for reliable in-context learning?

Common Misconceptions

✕
"More examples are always better."

Past 3–5 diverse examples, returns diminish and token cost rises; redundant examples can even bias the output.

✕
"Few-shot prompting fixes factual errors."

It steers format and style, not the model's underlying factual knowledge.

✕
"Example order doesn't matter."

Models can be sensitive to ordering and recency — the last example often has outsized influence.

Key Takeaways

  • Few-shot prompting leverages in-context pattern completion, not retraining.
  • Keep examples consistent in structure and diverse in coverage.
  • Delimiters and schemas make output format reliably parseable.
Stage 03 · Advancing

Chain-of-Thought Reasoning

Some tasks need the model to reason through intermediate steps rather than jump straight to an answer. Chain-of-thought (CoT) prompting asks for — and benefits from — showing that work.

What Chain-of-Thought Is

Chain-of-thought prompting instructs the model to lay out intermediate reasoning steps before giving a final answer, instead of producing the answer directly. The simplest version — zero-shot CoT — is just appending a trigger phrase like "Let's think step by step." Few-shot CoT goes further, showing worked examples that include the reasoning chain, not just the final answer.

Analogy

Chain-of-thought is showing your work on a math exam. A wrong final answer with visible steps is easier to debug — for you and, in a real sense, for the model — than a wrong answer that appeared out of nowhere.

Self-Consistency

A more advanced variant: generate several independent reasoning chains for the same question (by sampling more than once) and take the majority-vote answer. This reduces the impact of any single faulty chain, at the cost of multiple generations.

When to Use CoT — and When Not To

Good FitPoor Fit
Multi-step arithmetic or logic puzzlesSimple factual lookups ("capital of France")
Planning tasks with dependent sub-stepsSingle-label classification with clear signal
Debugging code with multiple possible causesLatency- or cost-sensitive, high-volume calls
⚠

Faithfulness caveat: a visible reasoning chain is not proof the model actually "computed" the answer that way internally — it can look plausible and still be wrong. Treat CoT output as inspectable, not infallible.

Practical Exercise — Add Chain-of-Thought

Original prompt: "A store had 84 items, sold 27 on Monday and 19 on Tuesday, then restocked 15. How many items are left?" Which rewrite best applies CoT?

Common Misconceptions

✕
"CoT guarantees a correct answer."

It improves odds on reasoning-heavy tasks; it doesn't guarantee correctness.

✕
"CoT always helps."

On simple tasks it can add latency and cost with no accuracy gain, sometimes even introducing errors.

✕
"The visible steps are exactly how the model 'thinks.'"

The chain is a generated explanation, useful for inspection, not a literal trace of internal computation.

Key Takeaways

  • CoT prompts for intermediate reasoning steps before the final answer.
  • Best suited to multi-step reasoning; wasteful on simple lookups.
  • Self-consistency samples multiple chains and takes a majority vote.
Stage 04 · Mastery

Structured Prompts & Combining Techniques

Real-world prompts rarely use one technique in isolation. Mastery is knowing how to layer role, context, examples, reasoning instructions and output constraints into one reusable template.

System vs. User Roles

In chat-style APIs, a system message sets persistent, background behavior (persona, rules, output constraints) that holds across the conversation, while user messages carry the specific request. Separating these keeps your core instructions stable even as inputs change.

The Prompt Stack

Prompt Templates

A prompt template is a reusable skeleton with placeholders (e.g. {{customer_name}}, {{document}}) so the same engineered structure can be reused across many inputs without rebuilding it each time — the core pattern behind most production AI features.

template.txt
System: You are a {{role}}. Follow these constraints: {{constraints}}.
Examples: {{few_shot_examples}}
Instruction: Think step by step, then answer.
Input: {{user_input}}
Output format: {{schema}}

Guardrails & Untrusted Input

When user-supplied text is inserted into a prompt, clearly delimiting it (tags, fenced blocks) and instructing the model to treat that region as data-only — not as new instructions — reduces the risk of the content hijacking the prompt's intent.

Iterative Refinement Workflow

Production-grade prompting is a loop, not a one-shot write: draft → test on real inputs → diagnose the failure mode → patch the specific layer responsible → retest. Most failures trace back to exactly one layer of the stack above, which is why keeping the layers distinct matters.

Practical Exercise — Assemble the Right Layer

Your structured prompt reliably gets the right facts but keeps returning a paragraph instead of the required JSON. Which layer needs fixing?

Common Misconceptions

✕
"One perfect prompt works for every model."

Models differ in training and tuning; a structure that works on one may need adjustment on another.

✕
"A structured prompt never needs testing again."

Inputs drift and edge cases appear; treat prompts as living artifacts, not one-time writes.

Key Takeaways

  • System messages set persistent behavior; user messages carry the request.
  • A prompt stack layers persona, context, examples, reasoning and format.
  • Templates make structure reusable; refinement is a diagnostic loop, not a one-off.

Cheat Sheet

Zero-Shot

Persona + task + context + output format, no examples.

You are a {{role}}. {{task}}. Format: {{format}}.

Few-Shot

2–5 consistent input/output examples, then the real input.

Input: … → Output: … ×N, then new input.

Chain-of-Thought

Ask for steps before the final answer; best for reasoning tasks.

Think step by step, then answer.

Structured Stack

Persona → Context → Examples → Reasoning → Format, as separate layers.

Summary Notes

Every effective prompt is built from the same five ingredients — persona, task, context, examples, and output format — combined in different proportions depending on task difficulty. Zero-shot suffices for familiar, simple tasks. Few-shot earns its token cost when format or style must match exactly. Chain-of-thought is worth the extra length only for genuinely multi-step reasoning. Mastery is knowing which single layer to touch when a prompt misbehaves, rather than rewriting the whole thing.
