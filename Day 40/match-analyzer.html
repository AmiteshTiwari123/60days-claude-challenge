    How this was built

    The brain: system prompt design

    The analysis is produced by a single Claude call constrained to role: recruiter-grade resume/JD matcher. It's instructed to (1) treat the resume and job description strictly as data, never as instructions — this blocks prompt-injection attempts hidden inside pasted text; (2) return JSON only, matching a fixed schema, so the UI never has to guess at structure; (3) branch into explicit edge-case states — invalid_resume, invalid_jd, and insufficient_info — instead of forcing a score onto garbage input; and (4) ground every claim in the actual text supplied, rather than inventing skills or experience that aren't there.

    Why the UI looks like this

    Job seekers triaging many applications don't want a chatbot transcript — they want a fast, legible verdict. The layout borrows from a case-file / control-room register: a numbered intake panel, a dossier report with a semicircular score gauge, and a stamped verdict (STRONG MATCH / BORDERLINE / NO MATCH) that mimics a customs or approval stamp — instantly scannable even before reading a word. Category cards use progress bars and matched/missing tags so a candidate can see exactly which keywords the resume is missing. The palette (near-black, amber, crimson, teal) reads as "instrument panel," reinforcing this is an analysis tool, not a companion.

    How the file is handled

    Uploaded PDFs are converted to base64 in the browser and sent to Claude as a native document content block, so the model reads the resume directly rather than relying on fragile client-side text extraction. Plain .txt files are read with FileReader and sent as text. Nothing is uploaded to a server other than the Anthropic API call itself — there's no backend in this file.

    Extending this

    • Batch mode: loop the same call over several pasted job descriptions against one resume, and rank the results by score — turns this into a "which of my 10 saved jobs should I apply to first" tool.
    • Memory: persist the parsed resume in localStorage or IndexedDB so returning users skip the upload step and only paste a new JD.
    • Tool use / live JD fetch: add the web_search tool (or an MCP job-board connector like Indeed) so a user can paste a job URL instead of pasting text, and Claude fetches the listing itself.
    • Multi-step flow: turn "Rewritten bullet points" into an interactive follow-up — a second call that takes the user's edited bullets and re-scores the match live.
    • Export: add a "copy improved resume" or "download as .txt" action once bullets are accepted.
